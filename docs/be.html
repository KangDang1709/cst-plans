2. Lambda Functions & Firebase Integration

POST /create-exam-room

Request Body (Flow 1: Start Now)

{
  "roomName": "Kiểm tra Toán Chương 3",
  "subject": "Toán",
  "grade": "Lớp 6",
  "durationMinutes": 60,
  "mode": "auto_advance",
  "assignmentId": "assign123",
  "startNow": true
}

Lambda auto-calculates: publishAt = UTC now + 10 minutes (students can join waiting room during this 10-min buffer)

Request Body (Flow 2: Scheduled Start)

{
  "roomName": "Kiểm tra Toán Chương 3",
  "subject": "Toán",
  "grade": "Lớp 6",
  "durationMinutes": 60,
  "mode": "auto_advance",
  "assignmentId": "assign123",
  "startNow": false,
  "publishAt": "2025-01-15T14:00:00Z"
}

Teacher specifies: publishAt timestamp (students can join from this time until exam end)

Handler Flow

  1. Validation
    • JWT → extract teacherId
    • Fields: roomName, subject, grade, durationMinutes (15-180), mode, assignmentId
    • If startNow=false: verify publishAt is ISO 8601 timestamp in the future
  2. External Validation
    • Assignment Service: GET /assignments/{assignmentId} → validate + question count
    • Verify subject + grade are valid
  3. Generate IDs
    • examRoomId = UUID
    • joinCode = 6-char alphanumeric (A-Z, 0-9), verify unique
  4. Create DynamoDB
    • state = "WAITING" (both flows) — room is now published/created
    • If startNow=true: publishAt = now + 10 minutes (auto-calculated by Lambda)
    • If startNow=false: publishAt = teacher-provided timestamp
    • Create EventBridge rules for publishAt and (publishAt + durationMinutes)
  5. Create EventBridge Rules (both flows)
    • Start rule: at({publishAt}) → triggers handle-scheduled-exam-start (exam begins, students see questions)
    • End rule: at({publishAt + durationMinutes}) → triggers handle-scheduled-exam-end (students auto-submit)
    • Both rules have event.examRoomId in input payload
  6. Firebase & EventBridge Both flows:
    • Exam room published immediately (state="WAITING")
    • EventBridge rules created for publishAt (start) and end times
    • Students can join waiting room from creation until publishAt
  7. Response
    • Return 201 Created: examRoomId, joinCode, status="PUBLISHED", publishAt, endAt (publishAt + durationMinutes)
✓ Flow 1 (startNow=true): publishAt auto-calculated as now+10min → students join immediately in waiting room
✓ Flow 2 (startNow=false): publishAt from teacher → EventBridge rules created for both flows → automatic start/end at scheduled times

POST /start-exam (Teacher) — Flow 1 Only

Note: Only if room created with publishNow=true. If publishNow=false (scheduled), DO NOT show this button — scheduler handles state transition.

Handler Flow

  1. Validate JWT + examRoomId ownership
  2. Verify room state = "WAITING" AND publishNow=true
  3. Calculate durationMs = durationMinutes * 60_000
  4. Update DynamoDB: Set state→"IN_PROGRESS", startedAt→now()
  5. Firebase WRITE: Update exam-rooms/{examRoomId}/state with:
    {
  "state": "IN_PROGRESS",
  "startedAt": 1705315200000,
  "durationMinutes": 90,
  "eventCount": 0,
  "timestamp": 1705315200000
}
  6. Both FE + Unity receive notification via Firebase listener
  7. Return 200 OK
⚠️ Firebase write targets same node regardless of action. Concurrent /start requests will overwrite each other (OK — idempotent state update).

POST /join-exam (Student)

Handler Flow

  1. Validate JWT (student token) → extract studentId
  2. Query by joinCode (GSI) → get examRoomId + room details
  3. Verify room state ∈ ["WAITING", "IN_PROGRESS"] (can't join after ENDED)
  4. Write DynamoDB ExamParticipants: Create entry with joinedAt=now(), hasSubmitted=false
  5. Firebase WRITE: Update exam-rooms/{examRoomId}/state (increment eventCount or update timestamp)
    {
  "state": "...",
  "eventCount": 5,
  "timestamp": 1705315300000
}
  6. Teacher receives Firebase notification → calls GET /participants → sees new student
  7. Return examRoomId + room metadata (durationMinutes, startedAt if IN_PROGRESS)

POST /submit-answers (Student)

Handler Flow

  1. Validate JWT (student token) → extract username
  2. Verify room state = "IN_PROGRESS" (can submit during exam only)
  3. Get assignment questions: GET /assignments/{assignmentId}/questions
  4. Validate answers against question types
  5. Calculate score based on correct answers
  6. Calculate complete_time = (now - startedAt) in seconds
  7. Check if submitted after exam end: is_late = (now > startedAt + durationMinutes)
  8. Call Assignment Service: POST /v1/assignments/{assignmentId}/submissions
    {
  "exam_room_id": "ROOM_456",
  "score": 85,
  "total_score": 100,
  "complete_time": 1800,
  "answer_details": { "q1": "A", "q2": "B" },
  "is_late": false
}
  9. Update DynamoDB ExamParticipants: Set hasSubmitted=true, submittedAt=now()
  10. Firebase WRITE: Update exam-rooms/{examRoomId}/state (increment eventCount)
    {
  "state": "IN_PROGRESS",
  "startedAt": 1705315200000,
  "durationMinutes": 90,
  "eventCount": 2,
  "timestamp": 1705315350000
}
  11. Teacher receives Firebase notification → calls GET /participants → sees submission count increased
  12. Return 201 Created + submissionId (from Assignment Service response)
✓ Submissions stored in unified Assignment Service table
✓ Query exams via exam_room_id GSI
✓ Exam context preserved for leaderboard calculations

POST /end-exam (Teacher)

Handler Flow

  1. Validate JWT + examRoomId ownership
  2. Verify room state = "IN_PROGRESS" (can't end if not started)
  3. Update DynamoDB ExamRooms: Set state→"ENDED", endedAt→now()
  4. Query ExamSubmissions + ExamParticipants for results
  5. Firebase WRITE: Update exam-rooms/{examRoomId}/state with:
    {
  "state": "ENDED",
  "endedAt": 1705332000000,
  "timestamp": 1705332000000
}
  6. Both FE + Unity receive notification
  7. Teacher calls GET /results; students see end screen
  8. Return 200 OK

GET /participants (Teacher)

Handler Flow

  1. Validate JWT + examRoomId ownership
  2. Query DynamoDB ExamParticipants where examRoomId = X
  3. Return array with all students: name, joinedAt, hasSubmitted, submittedAt
  4. No Firebase read (REST is source of truth for data)
✓ Called by FE after Firebase notification of /join or /submit

GET /results (Teacher)

Handler Flow

  1. Validate JWT + examRoomId ownership
  2. Verify room state = "ENDED" (can't get results before end)
  3. Query DynamoDB ExamSubmissions + ExamParticipants
  4. Join with Question answers (from Assignment Service)
  5. Calculate scores, sort by submission time
  6. Return leaderboard array

Scheduled Exam Processor (Flow 2 — publishNow=false with EventBridge)

Purpose

When teacher creates exam with publishNow=false and publishAt timestamp, EventBridge automatically triggers Lambda handlers at scheduled start time and end time without manual polling.

AWS EventBridge + Lambda Architecture

  • Teacher creates exam: POST /exam-rooms with startNow=true or startNow=false + publishAt
  • Lambda (create-exam-room):
    • Calculate publishAt: if startNow=true, then publishAt = now+10min; else use teacher-provided value
    • Save room to DynamoDB with state="WAITING", publishAt={calculated/provided}
    • Create EventBridge rule: at({publishAt}) → trigger start-exam-handler
    • Create EventBridge rule: at({publishAt+durationMinutes}) → trigger end-exam-handler
    • Return 201 Created: examRoomId, joinCode, status="PUBLISHED", publishAt, endAt

EventBridge Rule Configuration

Start Exam Rule (EventBridge Cron/One-time)
RuleName: "exam-{examRoomId}-start"
Schedule: "at(2025-01-15T14:00:00)"  // One-time rule
Target: Lambda function "handle-scheduled-exam-start"
RoleArn: "arn:aws:iam::ACCOUNT_ID:role/EventBridgeInvokeRole"

Input JSON:
{
  "examRoomId": "ROOM_456",
  "action": "START"
}
End Exam Rule (EventBridge Cron/One-time)
RuleName: "exam-{examRoomId}-end"
Schedule: "at(2025-01-15T15:30:00)"  // One-time rule (start + 90 min)
Target: Lambda function "handle-scheduled-exam-end"
RoleArn: "arn:aws:iam::ACCOUNT_ID:role/EventBridgeInvokeRole"

Input JSON:
{
  "examRoomId": "ROOM_456",
  "action": "END"
}

Lambda Handler: handle-scheduled-exam-start

  1. Get examRoomId from EventBridge event
  2. Fetch room from DynamoDB: GET ExamRooms where roomId={examRoomId}
  3. Verify state="WAITING" (idempotent check)
  4. Update DynamoDB: state→"IN_PROGRESS", startedAt→now(), update TTL
  5. Firebase WRITE: Update exam-rooms/{examRoomId}/state
    {
  "state": "IN_PROGRESS",
  "startedAt": 1705315200000,
  "durationMinutes": 90,
  "eventCount": 0,
  "timestamp": 1705315200000
}
  6. Students' Firebase listeners fire → timers start, questions display
  7. Delete this EventBridge rule (one-time execution)
  8. Return 200 OK

Lambda Handler: handle-scheduled-exam-end

  1. Get examRoomId from EventBridge event
  2. Fetch room from DynamoDB: GET ExamRooms where roomId={examRoomId}
  3. Verify state="IN_PROGRESS" (idempotent check)
  4. Update DynamoDB: state→"ENDED", endedAt→now()
  5. Firebase WRITE: Update exam-rooms/{examRoomId}/state
    {
  "state": "ENDED",
  "endedAt": 1705322100000,
  "timestamp": 1705322100000
}
  6. Students' Firebase listeners fire → auto-submit pending answers automatically
  7. Teacher can now call GET /results to see final leaderboard
  8. Delete this EventBridge rule (one-time execution)
  9. Return 200 OK

Teacher can still manually call POST /exam-rooms/{id}/start or POST /exam-rooms/{id}/end even if scheduled (overrides EventBridge).

3. Firebase Realtime Database Setup

Database Structure

exam-rooms/
  ├── {examRoomId}/
      └── state: { state, startedAt?, durationMinutes?, endedAt?, eventCount, timestamp }
      └── (no persistent event history — ephemeral only)

Firebase Initialization in Lambda

Node.js / TypeScript
import * as admin from 'firebase-admin';

// Initialize once at module level
const serviceAccount = JSON.parse(process.env.FIREBASE_CREDENTIALS);
admin.initializeApp({
  credential: admin.credential.cert(serviceAccount),
  databaseURL: process.env.FIREBASE_DB_URL
});

const db = admin.database();

// On state change, write to Firebase
async function updateExamState(examRoomId: string, state: any) {
  await db.ref(`exam-rooms/${examRoomId}/state`).set({
    ...state,
    timestamp: Date.now()
  });
}

Firebase Rules (Security)

{
  "rules": {
    "exam-rooms": {
      "$examRoomId": {
        "state": {
          // Only Lambda writes (via service account)
          ".write": "auth.uid === 'lambda-service-account-uid'",
          // FE + Unity can read
          ".read": "auth != null"
        }
      }
    }
  }
}

4. Infrastructure & Deployment

AWS Lambda Configuration

Environment Variables

  • DYNAMODB_EXAM_ROOMS_TABLE = "ExamRooms"
  • DYNAMODB_EXAM_PARTICIPANTS_TABLE = "ExamParticipants"
  • FIREBASE_DB_URL = "https://your-project.firebaseio.com"
  • FIREBASE_CREDENTIALS = JSON service account key
  • IDENTITY_SERVICE_URL = "https://identity-service.internal"
  • ASSIGNMENT_SERVICE_URL = "https://assignment-service.internal"

Runtime & Dependencies

  • Node.js 20.x (or C# 8.0 if using .NET Lambda)
  • firebase-admin@latest
  • aws-sdk v3 (DynamoDB client)
  • Timeout: 30s (sufficient for serial DynamoDB + Firebase writes)
  • Memory: 512MB (default)

IAM Permissions (Lambda Execution Role)

  • dynamodb:PutItem, dynamodb:UpdateItem, dynamodb:GetItem, dynamodb:Query on ExamRooms, ExamParticipants
  • events:PutRule, events:PutTargets, events:DeleteRule, events:RemoveTargets for EventBridge rule creation/cleanup
  • lambda:InvokeFunction on self (for EventBridge to invoke handlers)
  • Call Assignment Service to store submissions (no direct ExamSubmissions access)
  • dynamodb:GetItem with GSI on joinCode
  • No S3 needed (questions fetched from Assignment Service)

IAM Permissions (EventBridge Service Role)

  • lambda:InvokeFunction on Lambda handlers: handle-scheduled-exam-start, handle-scheduled-exam-end
  • Trust relationship: Allow service.events.amazonaws.com

DynamoDB Indexing

ExamRooms Table

  • Primary Key: examRoomId (HASH)
  • GSI: joinCode → allows rapid lookup by student code
  • TTL: Optional — set on endedAt to auto-delete old exams (e.g., 90 days)

ExamSubmissions Table

  • Primary Key: submissionId (HASH) + examRoomId (RANGE)
  • GSI: examRoomId + submittedAt → query results by room

ExamParticipants Table

  • Primary Key: participantId (HASH, format: examRoomId#studentId)
  • GSI: examRoomId + joinedAt → list all students in room

Error Handling & Logging

Errors from Each Endpoint

  • 400 Bad Request — Invalid JWT, missing fields, invalid assignmentId
  • 401 Unauthorized — Invalid/expired JWT, mismatched teacherId
  • 403 Forbidden — Teacher trying to access student data, vice versa
  • 404 Not Found — examRoomId not found, joinCode not found
  • 409 Conflict — State transition invalid (e.g., /start on room already IN_PROGRESS)
  • 500 Internal Server Error — DynamoDB/Firebase failure

Logging Strategy

console.log(JSON.stringify({
  timestamp: new Date().toISOString(),
  level: 'INFO',
  action: 'start-exam',
  examRoomId: 'xyz',
  teacherId: 'abc',
  durationMinutes: 90,
  dynamoSuccess: true,
  firebaseSuccess: true,
  duration_ms: 245
}));
  • Log all DynamoDB writes with success/failure + latency
  • Log all Firebase writes + eventCount (for concurrency tracking)
  • Log any failed calls to external services (Identity, Assignment)
  • Use CloudWatch Insights to query by examRoomId or error rate

  • ✓ DynamoDB tables created with correct indexes + GSI
  • ✓ Firebase project initialized, database URL configured
  • ✓ Firebase service account JSON in Lambda env var
  • ✓ Firebase rules allow Lambda writes + client reads
  • ✓ Identity Service integration tested
  • ✓ Assignment Service integration tested
  • ✓ Lambda IAM role has DynamoDB + env var access

Testing
  • ✓ Unit test: DynamoDB writes succeed
  • ✓ Unit test: Firebase writes succeed
  • ✓ Integration test: Create room → Join → Start → Submit → End (full flow)
  • ✓ Concurrency test: 10 students submit simultaneously (eventCount increments properly)
  • ✓ Edge case: Student joins after exam ended (should fail with 409)
  • ✓ Edge case: Teacher starts exam twice (should succeed idempotently or fail with 409)
  • ✓ Error handling: Simulate DynamoDB timeout → Lambda should retry + return 500
  • ✓ Firebase listener: Verify FE + Unity receive notifications within 1s
Post-Deployment Monitoring
  • Monitor DynamoDB latency (should be <100ms)
  • Monitor Firebase write latency (should be <500ms)
  • Alert on Lambda failures (error rate > 1%)
  • Alert on concurrent write conflicts (check eventCount increments)
  • Log exam duration + submission count for capacity planning
