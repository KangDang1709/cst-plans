Real-Time: Firebase Realtime Database

Single State Node Per Room

  • Lambda on REST action, updates state at: exam-rooms/{examRoomId}/state
  • FE + Unity both listen to same path — receive instant notification
  • Concurrent changes to same node → last write wins (no lost notifications)
  • Clients call REST endpoints when state changes to get full current data
  • Firebase SDK handles reconnects, auth, everything automatically
  • No polling. No WebSocket management. Firebase manages connections.

Architecture

🔐 Identity Service

  • Teacher login → JWT
  • Student registration + login → access token

📝 Exam Service (REST + Firebase writer)

  • All exam CRUD endpoints unchanged (DynamoDB)
  • On state-changing actions (/start, /end, /join, /submit), Lambda writes to Firebase
  • REST remains the source of truth for all data

🔥 Firebase Realtime Database

  • Single state node per room: exam-rooms/{examRoomId}/state
  • Contains: state ("WAITING", "IN_PROGRESS", "ENDED"), timestamps, metadata
  • FE + Unity both listen for changes — receive instant notifications
  • Concurrent writes to same node → last write wins (no lost notifications)
  • No persistent event history — state is ephemeral, REST is source of truth
  • Cost: Minimal transfer ($5-50/month for typical scale)

📚 Assignment Service

  • Exam service reads questions on-demand
  • FE/Unity don't call it directly
